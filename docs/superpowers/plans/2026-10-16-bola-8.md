# Bola 8 online — plano de implementação

> **Para quem executa:** SUB-SKILL OBRIGATÓRIA: usar superpowers:subagent-driven-development (recomendada) ou superpowers:executing-plans, tarefa por tarefa. Os passos usam checkbox (`- [ ]`).

**Objetivo:** bola 8 3D jogável online em `sinuca.fernandorffdev.com`, com lobby, link de mesa, até 4 jogadores (2 ou 2 duplas), efeito na branca e reconexão.

**Arquitetura:** a física 2D e as regras são TypeScript puro em `src/shared`, usado pelo navegador e pelo Worker. O Worker do Cloudflare serve o build estático e dois Durable Objects: `Lobby` (único) e `Room` (um por mesa), ambos com a API de hibernação de WebSocket. Quem tacou envia o resultado; a `Room` aplica as regras e guarda o estado como verdade.

**Pilha:** Vite 8, Three.js 0.186, TypeScript, Vitest 5, Wrangler 4 (versões medidas no npm em 16/10/2026).

**Spec:** `docs/superpowers/specs/2026-10-16-sinuca-design.md`

## Foco da revisão

Situações que a spec implica e que um amigo vai encontrar no primeiro dia. Cada uma tem um teste na tarefa dona:

1. **Celular bloqueia no meio da tacada** (quem tacou some antes de mandar o resultado) → depois de 10 s vale o resultado de outro aparelho, e a mesa não trava. *(Tarefa 3, `fallback result after 10s`)*
2. **Link com código errado ou mesa já apagada** → aparece "Mesa não encontrada" com um botão para o lobby, sem criar mesa fantasma. *(Tarefa 3, `hello to uninitialized room`)*
3. **O mesmo navegador em duas abas** (mesmo `playerId`) → a aba mais nova fica com o lugar e a antiga recebe "Mesa aberta em outra aba". *(Tarefa 3, `same playerId twice`)*
4. **Bola na mão em cima de outra bola ou fora da mesa** → a tacada é recusada e o jogador ajusta a posição. *(Tarefa 3, `rejects cue overlapping`)*
5. **Parceiro de dupla cai na vez dele** → o parceiro conectado pode jogar a vez. Com 2 jogadores, a mesa espera. *(Tarefa 3, `teammate shoots for disconnected partner`)*

```ts
// table.ts — unidades em metros
export const L = 2.54, W = 1.27, R = 0.028575;
export const POCKETS: { x: number; y: number; r: number }[]; // 0..3 cantos (0,0),(L,0),(L,W),(0,W) e 4..5 meio (L/2,0),(L/2,W); centro 0,6R para fora da borda; r: canto 0.062, meio 0.056
export const HEAD_X = L / 4, FOOT = { x: L * 3 / 4, y: W / 2 };
export type BallPos = { id: number; x: number; y: number; pocketed: boolean }; // id 0 = branca, 1..15
export function rack(): BallPos[]; // triângulo no FOOT, 8 no centro da 3ª fileira, quinas de trás uma lisa e uma listrada; ordem fixa; branca em (HEAD_X, W/2)
// physics.ts
export type Shot = { dx: number; dy: number; power: number; spinX: number; spinY: number }; // (dx,dy) unitário, power 0..1, spin no disco unitário
export type SimEvent =
  | { step: number; kind: 'hit'; a: number; b: number }
  | { step: number; kind: 'cushion'; ball: number }
  | { step: number; kind: 'pocket'; ball: number; pocket: number };
export function simulate(start: BallPos[], shot: Shot): { final: BallPos[]; events: SimEvent[]; frames: BallPos[][]; steps: number };
// frames: um a cada 4 passos (60 fps); final com posições arredondadas a 1e-6
```

**Modelo físico** (não sai da assinatura, por isso fica aqui). Cada bola tem `v` (velocidade) e `w` (velocidade do ponto de contato se rolasse, ω×R), além de `side` (efeito lateral, escalar):
- Tacada: `dir = (dx, dy)` vindo do `Shot`; `v = dir·power·6`, `w = dir·|v|·spinY·1.2`, `side = spinX·|v|·0.5`.
- Deslizando (`|v−w| > 1e-3`): `s = (v−w)/|v−w|`; `v −= μs·g·s·dt`; `w += 2.5·μs·g·s·dt`. Rolando: `w = v` e `v −= μr·g·v̂·dt` até parar. `side *= 0.995` por passo.
- Bola com bola (distância < 2R, aproximando): troca a componente normal de `v` com restituição 0.95; `w` não muda (é o que dá a puxada e a seguida); separa as bolas pela sobreposição.
- Boca da caçapa: a bola cujo centro está a menos de `r + R` do centro de alguma caçapa não reflete na tabela (passa direto para ser capturada).
- Tabela (o centro passa de R da borda, fora da boca de uma caçapa): inverte a normal de `v` e de `w` com restituição 0.75; soma `side·0.6` na tangente de `v` e zera `side`.
- Caçapa: centro dentro de `r` do centro da caçapa → `pocketed`, `v = w = 0`, evento `pocket`.
- Constantes: `g = 9.81`, `μs = 0.2`, `μr = 0.01`, `dt = 1/240`; para quando todo `|v|` e `|w|` fica abaixo de 0.005, ou com no máximo 240·20 passos.
- Os coeficientes podem ser ajustados até "parecer sinuca"; os testes abaixo não podem quebrar.

- **Imports com extensão `.ts`** em todo `src/shared` (`import { R } from './table.ts'`), com `allowImportingTsExtensions` e `noEmit` no `tsconfig`. Assim o Node 25 roda `scripts/smoke.mjs` importando `src/shared/physics.ts` direto, por remoção de tipos, sem `tsx`.

### Tarefa 3: Protocolo e máquina de estados da mesa

**Arquivos:** criar `src/shared/protocol.ts`, `src/shared/room.ts`, `tests/protocol.test.ts`, `tests/room.test.ts`.

**Interfaces:**
- Consome: `Shot`, `BallPos`, `SimEvent`, `R`, `L`, `W` (Tarefa 1); `EightState`, `newGame`, `applyShot` (Tarefa 2).
- Produz:
```ts
// protocol.ts
export type ClientMsg =
  | { t: 'hello'; playerId: string; name: string }
  | { t: 'start' } | { t: 'rematch' }
  | { t: 'sit'; seat: number | null }   // só em 'waiting': troca de assento livre (escolher parceiro) ou null = levantar e assistir (resolve mesa com 3)
  | { t: 'aim'; angle: number }
  | { t: 'shot'; shotNo: number; shot: Shot; cue?: { x: number; y: number } }
  | { t: 'result'; shotNo: number; final: BallPos[]; events: SimEvent[] };
export type ServerMsg =
  | { t: 'state'; room: PublicRoom; you: { playerId: string; seat: number | null } }
  | { t: 'shot'; shotNo: number; by: number; shot: Shot; balls: BallPos[] }
  | { t: 'aim'; seat: number; angle: number }
  | { t: 'error'; code: 'not_found' | 'other_tab' | 'not_your_turn' | 'bad_cue' | 'bad_start' | 'bad_msg'; msg: string };
export function parseClientMessage(raw: string): ClientMsg | null;
// rejeita: mais de 64 KB no `result` e mais de 2 KB nos demais, JSON inválido, `t` desconhecido, número não finito,
// power fora de [0,1], spin fora do disco, |(dx,dy)| fora de [0.999, 1.001],
// final com mais de 16 bolas ou events com mais de 1000 itens, playerId fora de /^[a-z0-9-]{8,40}$/.
// name: trim, remove < e >, corta em 20 caracteres; vazio → "Jogador".
// room.ts
export type Seat = { playerId: string; name: string; connected: boolean };
export type RoomState = {
  id: string; mode: 'eightball'; createdAt: number;
  seats: (Seat | null)[];                         // tamanho 4
  spectators: { playerId: string; name: string }[];
  phase: 'waiting' | 'aiming' | 'rolling' | 'over';
  game: EightState | null; shotNo: number;
  pending: { shotNo: number; by: number; shotAt: number; fallback: { final: BallPos[]; events: SimEvent[] } | null } | null;
};
export type PublicRoom = Omit<RoomState, 'pending' | 'seats' | 'spectators'> & {
  seats: ({ name: string; connected: boolean } | null)[];   // sem playerId: quem souber o id de outro pode tomar o lugar dele
  spectators: { name: string }[]; rolling: boolean;
};
export type Out = { to: 'all' | string; msg: ServerMsg };   // string = playerId
export type Input =
  | { kind: 'msg'; playerId: string; msg: ClientMsg }
  | { kind: 'disconnect'; playerId: string }
  | { kind: 'tick' };
export function createRoom(id: string, now: number): RoomState;
export function reduce(s: RoomState | null, input: Input, now: number): { state: RoomState | null; out: Out[] };
```

**Comportamento de `reduce`:**
- `hello` em mesa `null` → `error not_found` para quem enviou.
- `hello` com o mesmo `playerId` de alguém já conectado → envia `error other_tab` ao antigo (a casca do DO fecha o socket antigo) e o novo assume.
- `hello` com o `playerId` de um assento → reocupa o assento (`connected: true`). Senão: com `phase 'waiting'` e assento livre, senta; caso contrário, entra como espectador.
- `start`: precisa de 2 ou 4 assentos ocupados (3 → `bad_start`), compacta os assentos nas posições 0..n−1 e chama `newGame(n, 0)`.
- `shot`: só na `phase 'aiming'`, com `shotNo === s.shotNo`, e o remetente é o assento da vez **ou** um colega de time quando o assento da vez está desconectado. Com `cue`: precisa haver `ballInHand`; a branca fica dentro de [R, L−R]×[R, W−R], não encosta em outra bola (distância ≥ 2R) e, se for `'kitchen'`, x ≤ HEAD_X; senão `bad_cue`. Válida → `phase 'rolling'`, `pending`, e envia `shot` para todos com as bolas iniciais.
- `result`: o de quem tacou é aplicado na hora. O de outro jogador é aplicado na hora se `now − shotAt ≥ 10000`; antes disso, fica guardado como `fallback` (só o primeiro). `tick` com `now − shotAt ≥ 10000` e um `fallback` guardado → aplica o fallback.
- `sit`: só em `'waiting'`; assento livre → muda para ele; `null` → vira espectador; espectador com `sit` num assento livre → senta. Aplicar = `applyShot`, `shotNo++`, `phase 'aiming'` (ou `'over'` se tiver vencedor), e envia `state` para todos.
- `aim`: só de quem pode tacar; repassa para todos.
- `rematch` em `'over'`: `newGame` com a saída do time perdedor.
- `disconnect`: `connected: false`; o assento continua reservado.

### Tarefa 4: Worker e Durable Objects

**Arquivos:** criar `wrangler.jsonc`, `src/worker/index.ts`, `src/worker/lobby.ts`, `src/worker/room-do.ts`, `scripts/smoke.mjs` e um `index.html` provisório (só um `<h1>`).

**Interfaces:**
- Consome: `createRoom`, `reduce`, `parseClientMessage`, `Out`, `ServerMsg` (Tarefa 3).
- Produz (HTTP):
  - `GET /api/health` → `200 ok` (para esperar o servidor subir).
  - `POST /api/rooms` com `{mode:'eightball'}` → `{id}`: código de 4 letras do alfabeto `ABCDEFGHJKLMNPQRSTUVWXYZ`, sorteado de novo se já existir no Lobby; chama `Room.init(id)`.
  - `GET /ws/lobby` → WebSocket que recebe `{t:'rooms', rooms: {id, mode, players, phase}[]}` a cada mudança.
  - `GET /ws/room/:id` → WebSocket da mesa (o id é validado com `/^[A-Z]{4}$/`).
- Produz (RPC entre DOs): `Lobby.upsert(info)`, `Lobby.remove(id)`, `Lobby.has(id): boolean`, `Room.init(id)`.

`wrangler.jsonc`:
```jsonc
{
  "name": "sinuca",
  "main": "src/worker/index.ts",
  "compatibility_date": "2026-10-01",
  "assets": { "directory": "dist", "run_worker_first": ["/api/*", "/ws/*"] },
  "durable_objects": { "bindings": [ { "name": "LOBBY", "class_name": "Lobby" }, { "name": "ROOM", "class_name": "Room" } ] },
  "migrations": [ { "tag": "v1", "new_sqlite_classes": ["Lobby", "Room"] } ],
  "routes": [ { "pattern": "sinuca.fernandorffdev.com", "custom_domain": true } ]
}
```
- `Lobby` = `idFromName('lobby')`; `Room` = `idFromName(id)`.
- Hibernação: `ctx.acceptWebSocket(ws)`, `ws.serializeAttachment({ playerId })`, handlers `webSocketMessage` e `webSocketClose`. A `Room` carrega o estado de `ctx.storage.get('state')` na primeira mensagem depois de acordar e grava com `put` depois de cada `reduce` que mudou algo.
- A `Room` entrega o `out` do `reduce`: `'all'` vai para todos os sockets, e um `playerId` vai para o socket daquele jogador. No `other_tab`, fecha o socket antigo depois de enviar a mensagem.
- **Aba duplicada:** o attachment guarda `{ playerId, conn }`, onde `conn` é um número novo a cada `hello`, e a `Room` lembra o `conn` atual de cada `playerId`. `webSocketClose` só gera `disconnect` se o socket que fechou é o atual daquele jogador; o fechamento da aba antiga não derruba a nova.
- **Um alarme só por Durable Object:** depois de cada mudança, calcular o próximo prazo, que é o menor entre `pending.shotAt + 10_000` (com tacada pendente) e `vazioDesde + 10 min` (sem ninguém conectado), e chamar `setAlarm` com ele (ou `deleteAlarm` se não houver nenhum). O handler do alarme olha o estado para saber o que venceu: tacada vencida → `reduce(tick)`; mesa vazia há 10 min → `Lobby.remove(id)` e `ctx.storage.deleteAll()`.
- A `Room` chama `Lobby.upsert` sempre que o número de jogadores ou a fase muda.
